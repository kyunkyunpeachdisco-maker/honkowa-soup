本当にあった怖いスープ

謎はすべて実話。質問を重ねて真相を当てる水平思考クイズです。

    0手目
    Ctrl/⌘＋Enterで質問

    問題を作る・追加する

    1Claude に作ってもらう

    ボタンを押すと、作り方の指示文（検索先・ルールつき）がコピーされ、Claude が開きます。Claude の入力欄に貼り付けて送ってください。Claude が資料を検索して問題を作ります（Claude のサブスクで動き、APIキーは不要です）。

    2できた問題を貼り付ける

    Claude が返した問題データ（JSON）をそのまま貼り付けて「追加」を押してください。追加した問題はこの端末（データリポジトリを設定していればリポジトリ）に保存され、一覧の「共有」から1問ずつ友達にリンクで渡せます。

    親（出題者）を選ぶ

    親だけが答えを見られます。親は質問に答える役で、手番には入りません。

    参加用の QR コード

    参加する人は、自分のスマホのカメラでこの QR コードを読み取ってください。

    グループ

    遊ぶ人と審判（AI／人）をここで決めます。

    一緒に遊ぶメンバーを登録します。1台の端末を順番に回して遊びます。
    遊んだ・対戦中といった進み具合はグループごとに保存されるので、後日続きから遊べます。

    この端末がホストになって部屋を開き、ほかの人は招待リンクか QR コードで自分のスマホから参加します。問題はこの端末の問題集から選び、AI が審判のときはこの端末のキーを使います。部屋の番号はグループごとに決まっているので、同じ招待リンクを何度でも使えます。

    メンバーを変えても、対戦中の問題は始めたときのメンバーのまま続きます。

    遊び方

    実際の記録をもとにした水平思考クイズです。不思議な状況を手がかりに、「はい／いいえ」で答えられる質問を重ねて、真相を当てます。

    • 順番に1手ずつ、質問か解答をします。審判が記録をもとに答えます
    • だれかが真相を当てるか「降参」で終わり。得点がいちばん多い人の勝ちです
    • 行き詰まったら「ヒント」（得点は変わりません）。打ち間違えたら「1手戻す」
    • 遊ぶ人と審判（AI／人）は、一覧の上の ⚙ で決めます

    友達と遊ぶ
    • 1台を回す：⚙ でグループ名とメンバーを登録し、「〇〇の番です」の順に端末を回します。進み具合はグループごとに保存されます
    • 人が出題者：審判を「人が出題者」にすると AI なし・キーなしで遊べます。出題者が答えを見ながら、口頭の質問に答えます
    • チャットで遊ぶ：⚙ で入れると、この端末がホストになり、ほかの人は招待リンクか QR コードで自分のスマホから参加します（参加する人はキー不要・入るにはホストの許可が要る）。人が出題者のときは問題ごとに親を選び、答えは親にだけ見えます
    • 問題が終わると全員に星とコメントのアンケートが出ます（スキップ可）。評価は問題集のデータリポジトリに保存され、一覧の「★4.5（3）」から評価とコメントを見られます。「絞り込み」の「評価」でも探せます
    • 「問題と経過を共有」で、問題文とここまでの経過を LINE などに貼れます（答えは含まれません）
    問題を作る・共有する
    • 「＋ 問題を作る・追加」で、Claude に新しい問題を作ってもらえます（Claude のアカウントが必要）
    • 「問題集の保存・共有」で、問題集を自分の GitHub に保存し、招待リンクで友達に渡せます。友達に問題を追加してもらえば、答えを知らない問題を遊べます
    • 1問だけなら、各問題の「共有」からリンクで渡せます
    審判の答え方

    AI の審判は「はい／いいえ／部分的にはい／どちらとも言えない／重要ではありません／関係ありません／資料では不明／既出です」のどれかで答えます。的外れな質問や聞き直しは減点されます。人が出題者のチャットでは、親が「はい／いいえ／ややそう／ややそうではない／どちらともいえない／分からない／その他」で答えます。

    問題のもと（出典）

    公開された記録の、書かれた事実だけで作っています。どの記録から作ったかは問題文の最後に、記事名などは答え合わせの画面に出ます。

    • NASA ASRS CALLBACK：アメリカ航空宇宙局（NASA）の航空安全報告制度の月報。操縦士・管制官・客室乗務員などが、ひやりとした出来事を匿名で報告したもの（サイト）
    • NTSB：アメリカ国家運輸安全委員会の事故調査。飛行機・船・鉄道・バスなどの事故の原因を調べた報告（サイト）
    • Science Museum Group のブログ：ロンドンの科学博物館（Science Museum）とマンチェスターの科学産業博物館（Science and Industry Museum）の、収蔵品や調査についての記事（Science Museum・Science and Industry Museum）
    • Imperial War Museums：イギリスの帝国戦争博物館の解説記事（サイト）
    • MAIB：イギリス海難調査局の調査報告と、短い事例を集めた Safety Digest。商船・漁船・プレジャーボートの事故（サイト）
    • RAIB：イギリス鉄道事故調査局の調査報告と Safety digest（サイト）
    • CSB：アメリカ化学安全委員会の、工場などの化学事故の調査（サイト）
    • 失敗知識データベース：科学技術振興機構（JST）が作った、日本や海外の事故・失敗の事例集（サイト）
    必要なもの・データの保存先
    • AI が審判のとき：Google の Gemini APIキー（無料）。作り方は「設定」に載っています。予備に Groq のキー（無料）も入れられます
    • 人が出題者のとき・チャットの参加者：キーは要りません
    • キーや進行状況は、この端末のブラウザ内にだけ保存されます。質問の内容は Google（と、入れた場合は Groq）の AI に送られます

    評価

    問題を編集

    問題データ（JSON）を直して「保存」を押してください。データリポジトリにある問題は、リポジトリ側も更新されます。
    スマホで直すのが大変なときは、データリポジトリを claude.ai/code で開いて「〇〇の問題を直して」と頼むこともできます（終わったらプルリクエストをマージしてください）。
    編集している間にリポジトリ側が変わった場合は、上書きせずに保存を止めます。

    問題集の保存・共有

    追加した問題は、ふだんはこの端末だけに保存されます（ブラウザのデータ削除や、iPhone で7日使わないと消えることがあります）。
    GitHub に自分専用の非公開リポジトリ（データリポジトリ）を作っておくと、問題がそこに保存され、別の端末でも同じ問題集を使えます。友達には読み取り専用の招待リンクで問題集を渡せます。

    1データリポジトリを作る（任意）

    1. 非公開リポジトリの作成画面を開く（名前 honkowa-soup-data と非公開が入力済み）
    2. 「Create repository」を押す（README はあってもなくても構いません）

    既にあるリポジトリを使う場合は、この手順は飛ばしてください。

    2アクセス用のトークンを発行する

    1. トークン（Fine-grained PAT）の発行画面を開く（Token name に honkowa-soup が入力済み）
    2. Expiration：90 days か Custom で1年後（切れたら発行し直して貼り直すだけです）
    3. Repository access：Only select repositories → 手順1のリポジトリを選ぶ
    4. Permissions → Repository permissions：Contents を Read and write にする（ほかは触らない）
    5. 「Generate token」を押し、表示された github_pat_… をコピー

    この画面を閉じるとトークンは二度と表示されません。コピーしてから閉じてください。

    3アプリに設定する

    別の名前で作った・既存のリポジトリを使う場合は、そのリポジトリのページのURLを貼ってください。

    初回の保存時に、リポジトリへ案内ファイル（CLAUDE.md）を自動で作成します（既に CLAUDE.md があれば作りません）。claude.ai/code でこのリポジトリを開いて「問題を作って」と頼むと、Claude が案内ファイルに沿って問題を作り、リポジトリに追加します。Claude が作業用ブランチに保存した場合は、作られたプルリクエストを GitHub でマージ（Merge）すると、次にアプリを開いたときに出ます。
    複数の端末で使うときは、各端末で同じリポジトリとトークンを入れてください。トークンはこの端末のブラウザ内にのみ保存され、送信先は GitHub の API だけです。

    4友達に問題集を渡す（招待リンク）

    データリポジトリを非公開のまま、友達に渡せます。友達は GitHub アカウント不要です。招待リンクは2種類あります。

    1. トークンの発行画面をもう一度開く（Token name に honkowa-soup-friends が入力済み）
    2. Repository access：Only select repositories → データリポジトリを選ぶ
    3. Permissions → Repository permissions：Contents を Read-only にする（Read and write にしない）
    4. 「Generate token」→ 表示された github_pat_… を下に貼る

    5読み込んでいる友達の問題集

    6ファイルに書き出す・読み込む

    追加した問題（友達の問題集も含む）を1つのファイルに書き出せます。バックアップや、ファイルでの受け渡しに使えます。

    セットアップ

    このゲームは、出題者（審判）とAIプレイヤーを Google の Gemini AI が担当します。AIと遊ぶには Gemini のAPIキーが1つ必要です（一覧の上の ⚙ で審判を「人が出題者」にすれば、キーなしで遊べます）。
    回数が足りないときの予備として、Groq のキーも任意で追加できます。
    キーはこの端末のブラウザ内（localStorage）にのみ保存されます。送信先は Google（と、入れた場合は Groq）の API だけです。

    1Gemini APIキー（AIと遊ぶときは必須）

    1. Google AI Studio のAPIキー画面を開く（Googleアカウントでログイン）
      https://aistudio.google.com/apikey
    2. 「APIキーを作成」を押す
    3. プロジェクトを選ぶ画面が出たら 新しいプロジェクトで作成 を選ぶ
      既に使っているプロジェクトがあればそれでも構いません。迷ったら新規で。
    4. 表示された AIza… をコピーして下に貼る

    無料枠あり・カード登録不要です。キーは後から同じ画面で再表示できるので、控えを取り損ねても大丈夫です。

    新規と既存、どちらを選ぶべきか

    新規を勧めます。無料枠はプロジェクト単位なので、専用にしておけば他の用途と枠を食い合いません。不要になったらプロジェクトごと消せます。

    課金を設定したプロジェクトのキーは使わないでください。無料枠ではなく有料での利用として扱われることがあります。

    無料枠について

    1回の対戦で、質問のたびに審判とAIプレイヤーの呼び出しが発生します。1日に使える回数を超えると「上限に達しました」と表示されて止まります。進行は保存されているので、時間をおいて「再開」すれば続きから遊べます。

    無料枠では、入力した内容がGoogleのサービス改善に使われる場合があります。個人的な情報は入力しないでください。

    2モデルを選ぶ

    ふだんは標準のままで大丈夫です。審判は正確さが要るので標準、AIプレイヤーは軽量モデルにしています。無料枠の上限はモデルごとに決まっているので、分けておくと上限に当たりにくくなります。上限にすぐ当たるときは審判も軽量モデルにしてください（判定の正確さは少し落ちます）。

    3Groq APIキー（任意・回数が足りないときの予備）

    Gemini の無料枠は回数制限に当たりやすいため、別の無料AI「Groq」のキーも入れておくと、遊べる回数が増えます。入れなくても遊べます。

    1. Groq の API Keys 画面を開く（Google アカウントなどでログイン）
      https://console.groq.com/keys
    2. 「Create API Key」を押し、名前（例：honkowa-soup）を入れて作成する
    3. 表示された gsk_… をコピーして下に貼る
      この画面を閉じるとキーは二度と表示されません。控え損ねたら作り直してください。

    無料・カード登録不要。モデルは審判が gpt-oss-120b、AIプレイヤーが gpt-oss-20b です。キーはこの端末のブラウザ内にのみ保存され、送信先は Groq の API だけです。

    4「保存」を押す

    別の端末で遊ぶときは、その端末でも同じキーを入れてください。
